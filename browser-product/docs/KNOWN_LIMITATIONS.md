# Current release boundaries

The only enabled application adapter is the fictional scholarship portal. No authorized government login, authenticated application, real receipt or Mumbai deployment has been verified. Production startup remains disabled.

There is now a separate general browser framework, independent of the scholarship adapter, for observations, grounded tools, extraction, frames/shadow roots/tabs, PDF/image uploads and provider-neutral model decisions. It has an executable SDK and one-step injected model port; it has no bundled model or agent. Its unrelated fixture tests are scripted tool tests, not AI reasoning evidence. Generic network writes/authentication/final submit are deliberately denied; dedicated portal operations are explicit interfaces awaiting reviewed implementations. See INTEGRATION_AUDIT.md and GENERAL_BROWSER_V2.md. The updated source ZIP includes frontend assets and is verified after extraction in a fresh venv.

Implemented local controls include scoped encryption for profiles/provenance/artifacts, encrypted backup/restore, offline migration/key-ring rotation, signed core identity assertions with revocation and temporary operator grants, secure-cookie exchange, task-scoped invitations, direct challenge clicks/text/keys, streamed-body limits, request budgets, host validation, durable commands/reconciliation, retention, aggregate telemetry and Python/Node clients.

Default local-demo mode deliberately has no citizen login and must stay loopback-only with synthetic data. Signed mode needs actual core identity issuance over HTTPS; it is not an account directory or independent authentication provider. Encryption keys must be provisioned, protected, rotated and recoverable outside the code archive. Metadata such as routing IDs, pseudonymous subjects and timestamps is not full-disk encrypted. Old plaintext files/backups or external copies are not erased by field migration.

Interactive challenge control is verified only against our own fictional adapter. Actual CAPTCHA widgets, full official pages, iframes, device/face authentication and accessibility requirements need authorized adapter-specific validation. Return-to-WhatsApp is a configured navigation link, not message delivery. Core owns the WhatsApp round trip and graph resume.

Browser contexts remain memory-only. Recovery requires fresh human login/review. Mock submission reconciliation reads the authoritative fictional receipt store; each real adapter must implement its own reconciliation. SQLite action leases and request budgets are single-host controls, not a distributed job queue or WAF. Unknown in-flight commands remain blocked until core/operator reconciliation.

The concurrency benchmark covers six synthetic runs at concurrency two; it does not certify production capacity. Metrics/alert templates and a bounded monitoring script exist, but external alert delivery and real deployed operational response are unverified. Backup restore is tested to a new offline database, not an actual VM disaster-recovery exercise. Cleanup covers this service's records/artifacts, not WhatsApp, core vault, browser/OS swap, external storage snapshots or backups.

Docker is unavailable here, so updated images/Compose are unbuilt. Deployment remains deferred by the user. The 2:32 silent recording demonstrates the actual local synthetic system; it is not a deployed government/WhatsApp demo. Actual teammate services, official adapter authorization, deployed identity/vault/key management, production load/security review and Mumbai HTTPS evidence remain release gates.
